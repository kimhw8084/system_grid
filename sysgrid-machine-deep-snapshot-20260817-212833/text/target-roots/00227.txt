## What v1.3.2 changes

### Exact `resume_verify` schema correction

- `resume_verify` now matches Stable Engine v1.0.4 exactly: it carries state ledgers and trusted recipes, but **no mutation patch**.
- Resume capsules are inspected, copied, and launched without patch-member lookup or digest validation.
- Git forward/reverse patch checks run only for `mutation`.
- Non-mutation modes that attempt to carry a patch fail closed.
- Exact repository branch, HEAD, upstream, dirty paths, pre hashes, and protected hashes remain proven before engine launch.
- The Stable Engine then verifies the retained post-state, executes every trusted recipe, and alone owns commit, push, remote equality, and clean-state proof.

### Existing convergence protections retained

- Exact live-engine reattachment after supervisor interruption.
- Verified completed-output recovery without product replay.
- One safe mutation retry only from complete exact pre-state proof.
- Replay refusal for post-state, unknown state, or ambiguity.
- Byte-identical Inbox duplicate convergence.
- Complete canonical diagnostic ZIP on platform failure.

### Existing safety and performance retained

- One non-blocking kernel lock.
- Exact engine SHA-256 and self-test.
- Complete capsule and package manifest coverage.
- Strict ZIP safety, CRC, decompression, and executable-member defenses.
- Canonical `.txt`, GNU-style `.sha256`, and JSON state-ledger compatibility.
- Resource-aware concurrent independent preflight with complete aggregate reporting.
- Content-addressed, SHA-verified, fsynced, atomic evidence publication.

## Performance boundary

The supervisor maximizes safe platform concurrency and exports detected CPU/memory capacity as resource hints. The immutable capsule and Stable Engine remain authoritative for product-test ordering and parallel test workers. The supervisor cannot safely invent new tests, skip gates, force-apply a patch, or replay an ambiguous mutation.

The intended useful outcomes are:

1. **PASS:** all declared product gates complete and delivery succeeds.
2. **Application findings:** the complete trusted test matrix returns review-ready product defects.
3. **Rare trust stop:** continuing would risk wrong or duplicate product mutation; one diagnostic ZIP is produced for exact recovery.
