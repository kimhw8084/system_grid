## One-command installation and qualification

Run from the directory containing the ZIP:

```bash
rm -rf SYSGRID_EXECUTION_SUPERVISOR_v1.3.1 && unzip -q SYSGRID_EXECUTION_SUPERVISOR_v1.3.1.zip && cd SYSGRID_EXECUTION_SUPERVISOR_v1.3.1 && ./INSTALL_AND_QUALIFY.command
```

The installer verifies the complete extracted tree before importing payload code, runs the 57-test released-byte suite, locates and self-tests the exact accepted engine, installs immutable versioned bytes and atomic wrappers, reruns the same suite from staged bytes, verifies the final installed tree, and creates:

`~/Library/Mobile Documents/com~apple~CloudDocs/SysGrid-Control/Outbox/UPLOAD_THIS_TO_CHATGPT.zip`

Upload that qualification ZIP for independent review. Installation never starts a product mutation.

## What v1.3.1 changes

### Exact capsule-state compatibility correction

- Canonical `STATE/pre_expected_dirty_paths.txt` newline ledgers are accepted directly and verified path-for-path.
- Canonical `STATE/pre_hashes.sha256` and `STATE/protected_hashes.sha256` ledgers are accepted in GNU `sha256sum` form, including explicit missing-file expectations.
- Existing JSON state ledgers remain supported for backward compatibility.
- State parsing is strict: invalid UTF-8, NUL bytes, duplicate JSON keys, duplicate paths, malformed ledger lines, repository escapes, and `.git` paths fail closed.
- Patch applicability now runs only after exact branch, HEAD, upstream, dirty-path, pre-hash, and protected-hash proof succeeds.
- Any residual patch mismatch returns bounded forward and reverse Git diagnostics naming the exact failing context instead of a generic `PATCH_STATE_FAILURE`.

### Convergence instead of rerun friction

- If a prior supervisor stopped but the exact Stable Engine process is still running, the next `sg` reattaches by PID **and exact command identity**, then waits for that one authorized execution.
- If the engine already produced a complete local artifact, `sg` verifies and publishes it without repeating product execution.
- If the engine ended without evidence, one automatic retry is allowed only when the complete capsule-declared pre-state and uniquely forward-applicable patch prove that product mutation never occurred.
- If post-state or any ambiguity exists, no retry occurs. A canonical diagnostic ZIP is produced instead.
- Byte-identical duplicate Inbox capsules are archived automatically and treated as one identity. Distinct capsules remain an explicit safety stop.

### Full useful feedback

- Independent preflight checks use available CPU capacity, execute concurrently, preserve partial successes, and aggregate every failure.
- Diagnostics include structured preflight results, exact mutation-state classification, bounded engine stdout/stderr, launch identity, and one safe next action.
- Progress is six-step and phone-readable.

### Existing protections retained

- One non-blocking kernel lock.
- Exact engine SHA-256 and self-test.
- Exact capsule filename, size, hash, schema, patch, manifest, and project validation.
- ZIP traversal, duplicate, symlink, special-file, executable, encryption, CRC, decompression, and ratio defenses.
- Exact repository branch, HEAD, upstream, dirty paths, pre-hashes, and protected hashes.
- Private local engine Outbox and exact RESULT/capsule/engine/exit-code correlation.
- Content-addressed, SHA-verified, fsynced, atomic publication.
- Complete distribution and installed-tree identity with no unlisted bytecode or hidden files.

## Performance boundary

The supervisor maximizes safe platform concurrency and exports detected CPU/memory capacity as resource hints. The immutable capsule and Stable Engine remain authoritative for product-test ordering and parallel test workers. The supervisor cannot safely invent new test commands, skip gates, force-apply an incompatible patch, or replay an ambiguous mutation.

The intended useful outcomes are:

1. **PASS:** all declared product gates complete and delivery succeeds.
2. **Application findings:** the full trusted test matrix returns review-ready product defects.
3. **Rare trust stop:** continuing would risk wrong or duplicate product mutation; one diagnostic ZIP is still produced for control-room recovery.
